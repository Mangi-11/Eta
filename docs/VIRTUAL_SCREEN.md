# Root 虚拟屏（实验性）

原型为 AI 分配独立 Android display，所有启动、截图和输入都指定该 display。支持 Android 14+，需要 Root 及 ROM 的多屏接口；目前仅验证了 vivo X200 Pro mini、Android 16 / OriginOS 6。

## 使用方法

1. 在「设置 → 虚拟屏（实验性）」开启虚拟屏，并启用设备直达工具。
2. 正常告诉 Eta 打开应用并操作即可。启用开关后，`launch_app`、`open_uri`、`observe_screen`、点击、长按、滑动、节点和文本工具统一自动路由到虚拟屏；首次需要屏幕时自动创建会话。`virtual_screen` 保留显式尺寸与生命周期控制。
3. 创建虚拟屏时显示独立预览通知，任务完成后仍保留；点击该通知或设置页「查看虚拟屏」打开查看页。圆角画面按比例完整显示；横屏应用在手机竖向查看区域中顺时针旋转 90°，以旋转后的宽高比占满可用区域。点击、长按、滑动和蓝色操作指示同步转换坐标；顶部左侧显示任务状态，右侧键盘图标展开或折叠宿主输入框，触控图标切换手动操作。底部提供紧凑的返回、主页和应用菜单三个导航键。蓝色落点和轨迹复用原有手势指示样式。
4. 需要输入时，先点击虚拟屏内的目标编辑框，再展开宿主输入框，用手机当前输入法编辑并发送。输入框默认折叠，支持中文、换行和 emoji。创建显示时也尝试设置本屏 IME 策略，原生输入法能否直接出现在虚拟屏仍取决于 ROM。

顶部任务标记反映实际运行、完成、暂停、失败或停止状态，点击打开最近 100 条操作的时间、来源与结果。AI 控制期间，画面四周显示彩色渐变跑马灯；任务结束后停止动画，成功时显示「已完成」，无响应或持续无进展时显示「已暂停，待确认」。查看页不显示分辨率或 DPI。

横竖屏切换使用应用当前方向，虚拟屏的逻辑宽高、截图和坐标随之更新。Root helper 只调整 Eta 持有的次要 display，不修改宿主屏方向；补充任务方向请求监听，处理 ROM 不自动旋转虚拟显示的情况。查看页的顺时针旋转仅作用于预览与手势映射，模型仍使用应用逻辑方向的截图和坐标。切换方向会废弃旧观察和正在进行的触摸，下一次操作需重新观察，避免点击旧位置。

获准熄屏运行时，从创建起保持 CPU 与虚拟显示组唤醒，直到会话释放。显示唤醒锁绑定该虚拟屏的 display ID，且创建前确认显示组独立；主屏仍使用自身锁屏与电源策略。这样主屏熄灭后，横屏切换与触摸仍可由虚拟屏应用处理，空闲清理策略继续生效。

虚拟显示通过 Android 14+ 的 [setRequestedRefreshRate](https://developer.android.com/reference/android/hardware/display/VirtualDisplayConfig.Builder#setRequestedRefreshRate(float)) 请求 120 Hz，实际模式由 ROM 决定。查看页的 JPEG 抓帧和轮询间隔均为 100ms，编码最多 10 次/秒；未产生新 Surface 画面且没有主动观察请求时沿用缓存。用户未进入查看页或切出时停止持续编码，后台 `observe` 请求按需编码一帧，完成后立即停止；实际预览帧率受编码、传输与解码速度影响。

隐藏时仍排空 `ImageReader` 并保留最多一个最新原始缓冲，避免阻塞虚拟屏的绘制，也让静止页面能被再次观察；不会持续创建 Bitmap、计算指纹或编码 JPEG。后台无 UI 树的进展检查仍可按需获取指纹，保留原有停滞保护。Root 端的预览心跳在 1.5 秒没有续约后到期，防止查看器崩溃或连接断开后持续编码；正常退出查看页会立即撤销。查看器可见状态使用独立 `preview` 消息，不改变运行状态或空闲超时设置。实机验证记录见 [抓帧验证](FRAME_CAPTURE_2026-10-09.md)。

默认匹配手机主屏的分辨率、宽高比和 DPI（本机为 1216×2640、560 dpi），较大屏幕按同一比例缩放到最高 1440×3200、640 dpi，保留应用逻辑尺寸。可通过 `virtual_screen.create` 显式设置尺寸与 DPI。同一对话在成功、用户停止或模型失败后沿用虚拟屏和应用状态，新一轮必须重新观察；其他对话首次调用时可替换空闲虚拟屏。每次运行独占屏幕，上一轮延迟取消不会影响下一轮；查看页读取同一会话的 JPEG 帧，将触控按画面的实际缩放与留白换算到虚拟屏像素；单指手势在松开时提交，留白和多指手势不发送输入。手动输入与 AI 工具串行执行；用户操作后旧节点和坐标观察会失效，AI 必须重新观察。创建失败或 display 消失时返回明确错误；默认不回退主屏。

## 与主屏的关系

固定 `app_process` Root 子进程持有 `ImageReader` Surface，采用 own-content、own-focus、禁止抢夺顶层焦点及移除时销毁内容等 display 标志；不镜像主屏、不捕获安全 Surface。Root 点击、长按、滑动和按键通过指定 display ID 的 `InputManagerGlobal` 注入，并读取系统的输入完成结果；焦点文本粘贴仍通过指定 display 的 Root/shell 执行。

为减少任务迁移，启动会检查其他 display 上是否已有该应用任务。同一虚拟屏可重新进入；其他屏幕已有任务时按下方冲突策略处理。`singleTask` 只有在目标应用没有其他任务时才允许启动，`singleInstance` 和不支持缩放的 Activity 仍拒绝，并在启动后校验任务所在 display。尚未验证的 ROM 不能视为已经支持。独立显示不等于独立应用数据，登录状态、应用服务、通知及进程仍可共享。

无障碍连接可用时，UI 树和节点动作只查询该 display 且包名匹配焦点应用的窗口。窗口/服务未就绪返回 `ui_tree_pending`；同一应用窗口至少三次空树观察（间隔至少 500ms、跨越至少 1.5 秒）后，才以 `ui_tree_disabled` 暂时隐藏节点工具。每次请求 UI 树的观察仍会探测，节点恢复立即解除限制；应用、窗口、会话变化或用户手动操作也重置判定。缺树时默认观察附截图，保留 Root 坐标及焦点文本输入；恢复节点后必须使用新观察，旧索引不会复用。主屏观察也校验 display，不读取虚拟屏窗口。Root 普通 `uiautomator dump` 不能可靠获得这台 vivo 的虚拟屏树，因此没有用主屏节点替代。焦点文本通过指定 display 的 Root/shell 粘贴输入；指定节点的修改仍要求有效节点。粘贴暂时使用系统剪贴板，正常结束且剪贴板未被其他操作改写时恢复原内容；辅助进程被强制终止等异常不能保证恢复。

虚拟屏观察的 `focus.display_id` 和 `execution_scope` 明确当前屏幕归属，并单独报告主屏是否锁定。全局窗口列表和全局 `mCurrentFocus` 不能作为虚拟屏焦点或输入被阻挡的依据；主屏出现指纹窗口不代表虚拟屏被覆盖。已获熄屏许可时，应以对应 display 的观察和实际输入结果判断。

原型没有独立 IME、任意应用克隆、多指手势或任务迁移。主页和应用菜单使用 Eta 的独立导航页，只列出当前 display 的任务，切换前后校验任务归属；不会调用主屏桌面或系统全局最近任务。通知栏、系统面板、闹钟/计时 Intent 和内置浏览器 GUI 等无法隔离的 UI 操作默认拒绝；纯网页读取等工具不受影响。关闭虚拟屏开关会终止本次运行的后续 UI 操作。

## 应用已在其他屏幕运行

「自动停止冲突应用并在虚拟屏运行」默认关闭。遇到 `APP_ALREADY_RUNNING` 时，应用内弹窗和可用的通知提供三个选择：停止目标应用并在虚拟屏重新打开、在主屏继续、取消任务。该冲突选择不要求开启普通的「允许请求回退主屏」，通知不可用时仍能在 Eta 内选择。

开启自动停止设置后，Eta 自动停止冲突目标应用，再在虚拟屏启动并核对 display。停止会丢失目标应用未保存的内容，因此不会停止 Eta 或系统应用，也不会仅凭模型传入 `restartApp` 就批准停止。选择主屏会释放虚拟屏并要求重新观察；选择取消会终止当前任务。

## 请求回退主屏

「允许请求回退主屏」默认关闭。开启后，应用不兼容、虚拟 display 不可用或某项 UI 操作无法隔离时，任务暂停并发出普通通知，说明当前操作需要改用主屏。只有点击「允许本次任务」才会授权当前运行；通知正文打开 Eta，不代表同意。允许动作要求解锁，通知权限或该通知渠道关闭时不会执行回退。

授权后释放本次运行的虚拟屏，清除旧节点和坐标，返回 `UI_DISPLAY_SWITCHED`；不会重放刚才失败的动作。AI 必须重新启动目标应用（如需要）并调用 `observe_screen` 获取主屏观察，再继续本次任务。许可不写入设置、不跨任务复用，且沿用原有设备工具权限和无障碍边界。

拒绝、移除通知、取消任务、等待超过三分钟或关闭开关，均不操作主屏，同一运行不会重复弹出申请。旧通知与过期令牌不能授权新任务；关闭虚拟屏或回退开关后，本次运行已获准的主屏 UI 操作也会停止。参数错误或旧观察失效只要求重新观察，不触发回退。

## 熄屏许可与资源释放

「允许熄屏执行」是单独的用户开关，默认关闭；仅在该开关开启且本次创建指定 `allowScreenOff=true` 时，Root helper 才创建可保持解锁的虚拟 display 并持有跟随会话释放的局部唤醒锁。它不会解锁或关闭物理屏幕。未获许可时，物理屏幕熄灭或锁定会拒绝后续操作。

成功、用户停止和普通模型/工具失败后均保留屏幕与预览通知，同一对话可继续操作。停止只取消本轮资源，释放运行租约，不销毁独立的虚拟显示；下一轮不能复用旧节点、焦点或坐标观察。空闲清理滑条提供 10 分钟、20 分钟、60 分钟、永不关闭，默认 20 分钟。任务运行期间不因空闲策略关闭，任务结束后开始计时；手动操作刷新计时，预览帧轮询不会延长寿命。修改设置立即通知现有会话；永不关闭持续持有资源，设置页提示可能导致内存泄漏。

撤销虚拟屏或直接控制许可、显式关闭、管道断开或达到空闲超时，才释放会话、display、Surface 和唤醒锁。取消不会等待 Root 输入锁，仍在途的动作效果需在续聊时核对。无响应或无进展导致的保护性暂停保留屏幕，沿用空闲清理规则。单次交互超时为 15 秒，取消不会等待正在读取的画面。本机已验证主屏锁定并熄屏时的虚拟屏计数点击；完整任务持续执行和其他 ROM 仍未验证。

## 无响应与持续重试保护

输入处理完成与操作目标达成分别判断。`input_finished=true` 只说明系统确认输入处理完成，不能证明发布、发送、支付或导航已经生效。工具结果通过 `progress` 报告连续未变化的尝试次数，较早提示重新定位或换路径；不自动重放动作，不因静止画面直接重启应用。

- Root 输入最多等待 8 秒，超时返回 `UI_INPUT_TIMEOUT` 并暂停本轮。动作可能已经执行，需要先核对状态。
- 系统输入连接明确标记当前虚拟屏焦点窗口 `responsive=false` 时，返回 `UI_APP_UNRESPONSIVE`。检查同时匹配 display、包名和窗口；其他屏幕的无响应、缺树、静止截图及历史 ANR 不作为该应用卡死的证据。不支持的系统输出格式标为未知。
- 没有观察到有效变化时，同一目标最多尝试 3 次，第 4 次执行前返回 `UI_NO_PROGRESS`；换点位或换动作最多累计 6 次，第 7 次拦截。48 像素内的坐标微调仍视为同一目标。此状态只表示效果未确认，可能是点偏、加载、观察失效或应用无响应。
- 操作后持续只读观察也有边界：累计至少 8 次未变化的观察、且距离首次尝试至少 30 秒后暂停。没有执行过动作的纯观察不会触发这条规则。

进展检测优先比较目标窗口的节点内容和可操作状态，忽略观察编号、帧号、时间文本和进度条本身；没有节点时采用图像差异指纹。窗口、应用或有效内容变化会清除尝试预算，正常任务不设总轮数上限。图像指纹是启发式，可能漏掉细微变化，持续动画也可能掩盖停滞；不能把它当成应用存活的证明。观察附带 `frame_id`、`frame_age_ms`，用于判断画面来源，静态界面的旧帧本身不表示异常。

暂停由本地执行器发出可信控制信号，停止本批次余下工具并保留已有结果。会话运行器遇到 `UI_NO_PROGRESS`、`UI_APP_UNRESPONSIVE` 或 `UI_INPUT_TIMEOUT` 时，在同一轮任务中先尝试停止并重启当前虚拟屏应用一次，再用 `observe_screen` 取得新观察，让模型核对此前未确认的动作并继续原任务。重启前再次核对 display、应用和手动操作代次，不停止系统应用、Eta 或其他屏幕上的应用；普通模型、网络和权限错误不触发恢复。此恢复针对已经在虚拟屏中的应用，其他屏幕的应用冲突仍按原有授权设置处理。

重启会清除旧 UI 树、进展预算和暂停状态，并等待新的画面输出；原工具批次中的未执行动作不会重放。已获得熄屏许可时，恢复前确认目标属于独立显示组，冷启动使用仅绑定该 display 的屏幕唤醒锁，随会话释放；共享或未知显示组在停止应用前拒绝。这不会唤醒或解锁物理屏幕。恢复失败或再次出现保护性暂停时，本轮结束并保留虚拟屏，会话显示「已暂停，待确认」与重启结果，结果传输和归档保留暂停分类，不显示 `Runtime failed`。模型可见 JSON 不能伪造可信暂停或重启控制信号。查看页停止控制边框动画，用户仍可手动处理；同一对话的新一轮消息可重新观察并继续。取消、撤销许可和空闲超时仍会释放屏幕。
