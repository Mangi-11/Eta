# 自动记忆与操作经验

Eta 在成功完成普通任务后启动独立复盘，沿用原任务的模型配置。复盘会产生额外模型请求；可在「设置 → 记忆」分别关闭自动记忆、自动技能。关闭记忆总开关后，复盘也不能读取或写入现实记忆。角色会话不参与复盘。

## 从完成任务到下次复用

1. Runtime 提交最终结果与脱敏后的执行记录，再发起复盘；界面退出不会立即取消复盘。
2. 复盘读取相关记忆和技能，判断哪些事实、方法值得保存。多次 GUI 操作、失败后成功，或用户明确要求总结技能，会启用技能复盘。
3. 持久事实与偏好写入原有 `MEMORY.md`；操作流程写入用户技能目录的 `SKILL.md`。后续任务先接收技能描述，再通过 `skills_read` 按需加载正文。
4. 新前台任务会取消旧复盘，优先执行用户当前请求。设置页仍可编辑记忆、停用或删除技能。

技能应包含适用应用及版本、前置条件、可重新观察的操作步骤、实际遇到的陷阱，以及可核验的完成条件。复盘提示要求排除固定坐标、临时节点编号、密码、验证码、私人数据正文和未经确认的成功步骤；总结质量仍取决于原任务证据与模型。

## 工具与写入边界

`skills_manage` 支持 `create` 和 `update`，例如：

```json
{"action":"create","skillId":"calendar-create-event","description":"在已验证的日历界面创建日程并确认保存","bodyMarkdown":"# 创建日程\n\n## 前置条件\n...\n\n## 步骤与验证\n..."}
```

更新必须携带 `skills_read` 返回的 `expectedRevision`。只能修改已启用的用户技能；内置技能、禁用技能、符号链接及冲突版本不能覆盖。已有资源和额外 frontmatter 保留，安装沿用 ZIP 校验、事务和恢复日志。当前运行已冻结的技能不会中途更换，更新从下一次运行生效。

后台复盘只公开记忆与技能工具，不能调用设备、终端、MCP、网络检索或任务工具；最多 4 轮、12 次工具调用、180 秒，每次最多追加一段记忆和提交一个技能。自动记忆只允许 `append`，必须通过 revision 检查，不允许清空或覆盖原文。人工对话中的既有记忆编辑能力保持可用。

## 验证与参考

JVM 测试覆盖权限名单、角色会话边界、证据裁剪、版本冲突、资源保留和取消。vivo Android 16 真机使用本机模拟模型验证了「任务完成 → 后台追加记忆 → 注册用户技能」，并确认测试记忆、技能和模型选择全部恢复；这验证执行链路，不代表真实模型的总结质量。

参考 Hermes 的 [后台复盘](https://github.com/NousResearch/hermes-agent/blob/6590f13a1ba21b18224a0f53ef2ead004b5fa7d6/agent/background_review.py) 与 [技能管理](https://github.com/NousResearch/hermes-agent/blob/6590f13a1ba21b18224a0f53ef2ead004b5fa7d6/tools/skill_manager_tool.py)。Eta 的实现使用现有 Android Runtime、记忆存储和技能事务。
