# 通知中心与学习审批

侧边栏的「通知中心」显示模型提出的现实记忆和用户技能方案，支持全部、待审批、详情、同意、拒绝和继续完善。
`memory_write` / `skills_manage` 现在提交方案，返回 `proposal_id` 和 `applied=false`；后台经验复盘也走相同入口。
角色专属剧情记忆继续保存在角色自己的空间，现实记忆在角色会话中仍只读。

方案写入 Room 数据库，正文不会进入诊断日志或工具归档。相同版本和内容的待审批方案跨会话去重，最多保留 200 个未决方案；队列满时拒绝新提交，不删除尚未审批的内容。
通知列表优先显示未决方案，历史记录保留最近 200 条。打开详情标记已读；同意前不会写入 `MEMORY.md` 或安装技能。

同意时先用数据库条件更新取得独占审批权，再检查当前权限、记忆 revision 或技能版本。并发或重复点击只执行一次；权限撤销不会被绕过，内容已变化则标记为过期，要求重新完善。
如果进程在写入与保存状态之间退出，下次启动把该方案标记为「结果待核实」，不自动重放。用户应先核对当前记忆或技能，再继续完善。

「继续完善」把方案和读取最新版本的要求放入新会话草稿，并将旧方案标记为完善中；用户可以补充要求后发送。该操作不自动批准旧方案。
清空记忆、替换行区间、新建技能和更新技能在详情中显示对应的操作类型，技能说明与正文可以完整查看。

数据库版本由 26 升到 27，仅增加 `learning_proposals` 表；上游与本分支的旧数据库迁移回归覆盖已有模型绑定、请求时长和自动任务数据。

交互参考 [QwenPaw 的 inbox 和审批入口](https://github.com/agentscope-ai/QwenPaw/tree/a211f474f7423a794de8b915c9a58efaa780970f)。Eta 的审批使用持久存储、版本检查与条件更新。
