# vivo 原子通知与原子岛

Eta 已有普通运行通知、当前工具名称和虚拟屏查看入口。vivo 原子岛部分目前实现了本地通知扩展字段，**尚未完成正式平台接入或真机原子岛展示验证**。

## 当前实现

`VivoAtomicNotification` 按官方协议封装基础卡、小卡及左右岛：左侧 Eta 图标，右侧当前工具；点击复用运行通知的 `PendingIntent`。虚拟屏活跃时打开查看页，其余时候打开 Eta。更新使用递增的 `changedRecord`，同时保留普通通知。

仅 vivo 设备且手动配置了场景 ID 时附加字段，默认场景为空。「设置 → 虚拟屏」中的场景字段用于后续获批接入和调试；字符串格式校验不验证平台批准。项目未内置虚构的 `AGENT` 场景，也未集成 VPush SDK、注册设备 token 或实现远程推送更新。

## 正式接入步骤

1. 在 [vivo 开发者平台](https://dev.vivo.com.cn/)建立开发者账号及应用，核对 `io.github.mangi.eta` 的包名和签名归属。若平台要求不同包名，应先处理应用标识及现有 Hook/IPC 的兼容问题。
2. 按平台申请推送和原子通知能力，确认「AI 任务执行」对应的获批 `scene`。官方列出的场景例子不能视为任意应用的授权；没有该用途的场景时需向平台确认。
3. 按 [客户端 SDK 集成指南](https://dev.vivo.com.cn/documentCenter/doc/365)接入 VPush SDK，配置平台分配的 `app_id` / `api_key`，完成初始化、注册 token 和隐私说明。2026-10-06 查阅的指南给出 `v4.1.7.0_517`；实际集成应重新核对版本。服务端密钥不得放入客户端或 Git。
4. 按 [原子通知协议](https://dev.vivo.com.cn/documentCenter/doc/896)发送本地通知，核验创建、工具更新、点击查看与结束生命周期。如需要进程退出后的远程更新，再由应用服务端保存 `regId`、通知 ID 和场景，并使用 VPush 服务端接口。
5. 在获批应用签名、实际支持的 OriginOS 机型上测试通知权限、显示资格、锁屏入口和退出清理；测试通过前以普通通知提供进度。

截至当前，没有可用的获批场景或平台配置，因此没有声称 Root、填入某个场景名或发布普通通知已经实现原子岛。以上步骤来自 vivo 官方文档；开发者账号申请和平台审核需要应用所有者完成。
